# 建议专利名生成

何时执行：评估开始前主动询问是否需要建议名称。用户明确表示不需要时跳过整份文件，并在报告首部注明「本次未提供建议名称」。

每个建议名称都要比原名称在以下方面更优：领域更明确、技术手段更具体、区别点更突出、表达更简洁。

## 命名模板

```
[核心区别特征或技术手段] + 的 + [应用行业或场景] + [研究对象] + [处理动作] + 主题类型词
```

常用组合模式：
- 模式 1：`基于<具体技术手段>的<领域><对象><检测 / 识别 / 控制 / 预测 / 生成><主题类型>`
  - 示例：基于改进 YOLOv4 的变电站指针式仪表读数识别方法
- 模式 2：`<对象或场景>的<具体技术手段><主题类型>`
  - 示例：砂轮-工件接触弧区实时识别的自适应颤振抑制方法及系统
- 模式 3：`一种<具体技术手段>的<领域><对象><主题类型>`，「一种」可省略以压缩字数

## 生成规则

1. 必须基于权利要求 1 与说明书的核心区别手段（见 `novelty_search.md` 第 1 步的 C1…Cn），不得脱离原文凭空命名。
2. 必含三项要素：
   - 应用或行业领域，过宽者不可用
   - 具体技术手段，不接受「通过处理器」「智能算法」「基于 AI」
   - 主题类型词（方法 / 装置 / 系统 / 设备 / 存储介质 / 芯片 / 终端等），按实际保护客体选择；多客体时写「方法及装置」，但不要堆砌三种以上
3. 尽量点出区别点，如「实时识别」「自适应」「双流融合」。
4. 禁止项：商业宣传语、商标、产品名、人名、单位名；同义重复堆砌（如「方法装置系统设备」全列）；「一种」之外的冗余虚词。
5. 字数：以 ≤25 字为佳，最多不超过 30 字。

## 质量初筛

生成后立即执行 `scripts/name_check.py`，检查：
- 字符数是否超限（超过 25 字标记提醒）
- 是否命中无实质技术含义的词（智能、高效、新型、改进的、优化、新一代、革命性、独家等）
- 是否缺少主题类型词
- 是否存在疑似型号代号（如大写字母加数字组合）

未通过检查的候选，直接在备注中标明原因，不进入推荐位。

## 输出格式

```
## 建议专利名备选清单

原名称：<原文>（NN 字）

| # | 建议名称 | 字数 | 技术手段 | 领域 | 区别点 | 备注 |
|---|---------|------|---------|------|--------|------|
| 1 | | | | | | 推荐：三要素齐全 |
| 2 | | | | | | 备选：突出 XX 区别特征，略长 |
| 3 | | | | | | 备选：更上位，稳定性高但区别度低 |
```

输出 3–5 个候选，按推荐度排序，第 1 个标注「推荐」。用 AskUserQuestion 让用户选择，用户选定后再按该名称继续评分流程。
